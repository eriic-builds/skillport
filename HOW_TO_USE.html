Set up the library

These steps connect Claude Code, Codex, Copilot, VS Code, and Antigravity to the same files.

1

Install the basics

Install Git, GitHub CLI, and Node.js 20 or newer. Then sign in to GitHub:

gh auth login
2

Use your template copy

On the public Skillport page, choose Use this template to create your own repository first. Then clone that copy:

gh repo clone YOUR_GITHUB_USERNAME/YOUR_REPOSITORY ~/skillport

Before running Doctor, edit .claude-plugin/plugin.json and .claude-plugin/marketplace.json so the owner and repository point to your new copy.

On Windows PowerShell, clone to "$HOME\skillport", then run & "$HOME\skillport\bin\skills.ps1" link (and the same pattern for every command below) instead of the bin/skills form.
3

Connect all local AI tools

~/skillport/bin/skills link

This creates safe links. It does not duplicate your skills.

4

Make the skills command easy to type

The rest of this guide, and GUIDE.md, use the short form skills .... Add an alias so that works:

echo "alias skills='~/skillport/bin/skills'" >> ~/.zshrc && source ~/.zshrc

Using bash instead of zsh? Append to ~/.bash_profile on macOS (login shells read that file, not ~/.bashrc), or to ~/.bashrc on Linux. On Windows PowerShell, add function skills { & "$HOME\skillport\bin\skills.ps1" @args } to your PowerShell profile.

Prefer not to? You can always type ~/skillport/bin/skills in full instead of the short form used below.

5

Check the setup

skills doctor
If Doctor only says Codex is not installed and you do not use Codex, your other clients can still work.

Manage your skills

Choosing your skills

Keep skills you use regularly, and shelf the others to reduce noise. Everything is saved in Git.

Active vs. Shelf — the mental model

Think of it like a bookshelf: your desk holds the books you're reading now (active skills), while the shelf holds books you keep but aren't using this week.

   shelf/                          skills/
   ┌──────────────┐                ┌──────────────┐
   │  📚 shelf    │  ← unshelve ─→ │  📖 desk     │
   │              │                │              │
   │  stored      │  ← shelve ───  │  in use      │
   │  not loaded  │                │  loads every │
   │              │                │  session     │
   └──────────────┘                └──────────────┘
          ↑
          └── skills shelf   (just look at what's stored)

shelve = put away (a verb, it moves something)

unshelve = take out to use (remove from storage)

shelf = look at what's stored (a noun, it only looks)

Command reference — the three skill commands

You want to… Run this Think of it as…
See what's stored skills shelf look at the shelf
Start using a skill skills unshelve <name> take it off the shelf
Stop loading a skill skills shelve <name> put it back on the shelf

A worked example: your library outgrows what you use daily

A fresh template starts with only 3 skills and an empty shelf, so this example describes what happens later, once you've added skills you don't need every day — for instance, after importing a few extra ones from GitHub.

Step 1: See what's currently active

skills list

Output: every active skill, plus a summary line like "9 active · 4,100 chars · 41% of budget". If that count is more than you use in a normal week, some are candidates for the shelf.

Step 2: Put away what you're not using this week

skills shelve some-rarely-used-skill

Output: the skill moves from skills/ to shelf/. It's still in Git, just not loaded by any client.

Step 3: Later, see what's stored

skills shelf

Output: "The shelf is empty." until you've shelved something — then each shelved skill and its description.

Step 4: Bring one back when you need it

skills unshelve some-rarely-used-skill

Important: AI clients cache their skill list at startup. The skill is ready, but the client must be restarted to see it.

Two common mix-ups

Mix-up #1: "shelf" and "shelve" are too similar"

shelf is a noun — it's the container; it only looks.

shelve is a verb — it's an action; it moves something.

Just like: "I looked at the shelf. I shelved the book."

Mix-up #2: "Does shelve turn a skill on or off?"

Off. Shelving a book means putting it away, storing it. So skills shelve <name> stops a skill loading. The skill is still there, safe in Git, just not active.

What the skill-shelf skill does

You don't have to remember these commands. There's a skill called skill-shelf that does this work for you — once your shelf actually has something on it.

Once you've shelved a skill, try saying something like:

I need a skill for writing release notes

The skill will:

  1. Show you matching skills from the shelf with their descriptions
  2. Ask for your confirmation before moving anything
  3. Run the unshelve command
  4. Tell you to restart your AI client

Always confirm: The skill-shelf skill will always show you what it found and ask before doing anything. It never silently changes your skills. On an empty shelf, it will simply tell you there's nothing there.

1

Claude Code, Codex, Copilot CLI, VS Code, and Antigravity

If Setup step 3 finished without errors, every installed local client already reads this library. Antigravity is linked only when skills link detects it installed; GitHub Copilot CLI is registered only when the copilot CLI itself is installed. Restart whichever ones you use, then confirm inside each:

What skills do you have available?

Claude Code and Copilot Chat in VS Code both read ~/.claude/skills. Codex reads a symlink per skill under ~/.codex/skills (and ~/.agents/skills). GitHub Copilot CLI reads a registered path instead of a symlink. Antigravity links only if skills link detects it installed.

Multi-file skills and Copilot CLI: Copilot CLI only reads files under its current working directory, so a skill with supporting files beyond SKILL.md needs one alias in your shell profile: 
alias copilot='copilot --add-dir ~/skillport'
On Windows PowerShell: function copilot { copilot.exe --add-dir "$HOME\skillport" @args }. skills doctor flags this as missing when it applies.
2

Cowork: add your marketplace

Open a Cowork session in Claude Desktop and enter these commands there—not in Terminal:

/plugin marketplace add YOUR_GITHUB_USERNAME/YOUR_REPOSITORY
/plugin install skillport@skillport

Cowork may ask you to authorize GitHub for your repository.

Do not also install this marketplace in Claude Code. Claude Code already reads the same skills through ~/.claude/skills; installing the plugin there would create a duplicate delivery path.

After changing a skill

First publish from Terminal:

skills sync "update a skill"

Then update both the catalog and installed plugin inside Cowork:

/plugin marketplace update
/plugin update skillport@skillport
3

Claude Chat / claude.ai: upload one ZIP

These cloud surfaces cannot read your computer or GitHub plugin directly. Package only the skill you want:

cd ~/skillport/skills
zip -r ~/Downloads/commit-message.zip commit-message/

Then open Customize → Skills, upload the ZIP, and enable it.

Cloud uploads are copies. Upload a new ZIP after the skill changes. Do not upload the entire library unless you intentionally want one large cloud skill.
Troubleshooting

Fix the common problems

A skill is missing

Run skills link, then skills doctor. Restart the AI client afterward.

Cowork has an old version

Run both /plugin marketplace update and /plugin update skillport@skillport.

Copilot CLI can't read supporting files

Add the shell alias from the Connect clients panel, or run skills use <skill-name> in that project to sidestep it entirely.

Cloud Claude is outdated

Rebuild the single-skill ZIP and upload it again in Customize → Skills.

VS Code lists a skill twice

Expected — VS Code shows one entry per personal skills location (~/.claude/skills and ~/.agents/skills). Both point to the same file; nothing is duplicated on disk.

The universal first check: 
cd ~/skillport
skills doctor
